# 공개 릴리즈 상태

2026-11-09 보안 정리: 공개된 r1–r14 릴리즈와 태그를 내렸습니다. 이전 패키지에 조직별 사이트 설정이 포함된 사실을 확인했기 때문입니다. 해당 다운로드를 사용하지 마세요.

대체 릴리즈 r16 (`v1.30.6-r16`)은 범용 기본 설정(`example.com`, iframe 추가 허용 없음, 예시 경로)으로 빌드·검증을 완료해 공개했습니다. 9개 필수 환경 검증과 1,008개 검사가 모두 통과했습니다. 배포 아카이브와 릴리즈 설명에서 조직 도메인 흔적이 없는지 확인했고, SHA256SUMS가 네 개 배포 파일과 일치합니다.

`nginx.conf`의 `http {}`에 `client_body_temp_path temp/client_body 1 2;`를 지정합니다. 요청 본문을 처리하는 동안 사용하는 임시 경로이며, 영구 파일 저장은 백엔드가 담당합니다.

KISA WEB-16 대응은 `http {}` 전역과 기본 리스너에서 `server_tokens off` 및 `more_clear_headers Server`를 적용합니다. KISA WEB-22 기본 오류 문서도 `nginx.conf`의 `http {}`에 지정하고, 기본 리스너에서 내부 오류 페이지를 제공합니다. 일반 404/500 응답은 배포 오류 문서로 바뀌는지 검사합니다. TLS 포트에 온 평문 HTTP parser 오류는 NGINX가 직접 응답하므로 별도로 Server 헤더 제거를 검사합니다.

KISA 보고서의 WEB-09 서비스 계정과 WEB-26 로그 디렉터리 ACL은 Windows 운영체제 설정입니다. 이 작업 공간에서는 고객 서버에 접속하거나 해당 권한을 바꿀 수 없습니다. WEB-24는 업로드 경로 정보가 없어 수동 검토 상태입니다.

실제 서비스 도메인, 인증서, 웹 루트, backend 주소는 공개 배포본에 넣지 않습니다. 운영자는 배포 전에 `conf/site.conf`를 자신의 환경에 맞게 수정해야 합니다.
