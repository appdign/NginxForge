# 프론트엔드 코드 전용 점검·수정 프롬프트

아래 내용을 프론트엔드 저장소의 코딩 에이전트에 전달합니다.

```text
현재 프론트엔드의 코드에서 발생하는 보안 문제를 점검하고 수정·테스트해줘.
AGENTS.md, 프레임워크/버전, CSR/SSR 구조와 기존 Spring Boot 인증 연동을 먼저 확인해줘.
기존 정상 기능을 유지하고 사용하지 않는 기능은 근거와 함께 미대상 처리해줘.

범위:
- NGINX가 담당하는 TLS/HTTPS, HSTS, CSP/Permissions-Policy 등 응답 헤더,
  CORS, 쿠키 플래그, 요청 크기/빈도, 경로/IP 차단, HTTP 캐시 설정은 제외해줘.
- 빌드/배포 옵션이나 프레임워크 설정으로 해결되는 항목은 코드 수정 목록에서 빼고
  필요한 설정과 담당자를 별도 표로 정리해줘. 설정 파일이 Java/JS여도 같은 원칙을 적용해줘.
- 비밀값 제거 등 실제 소스/산출물에 잘못 포함된 데이터와 코드 결함은 수정 대상이야.
- CSP가 XSS를, HttpOnly가 토큰 저장 설계를, CORS가 인증/CSRF를 대체한다고 보지 마.

1. 안전한 출력과 코드 실행
[ ] 사용자 입력·API 응답·URL/저장소 데이터를 텍스트로 안전하게 출력하는가?
[ ] innerHTML·dangerouslySetInnerHTML·v-html 등 직접 HTML 삽입에 불신 입력이 들어가지 않는가?
[ ] 꼭 필요한 HTML/Markdown/에디터 미리보기에는 검증된 sanitizer와 적절한 허용 정책을 사용하는가?
[ ] 문자열을 eval·Function·이벤트 코드로 실행하거나 동적 템플릿에 주입하지 않는가?
[ ] 링크·이동 주소·파일 미리보기의 스킴과 목적지를 파싱·검증하는가?

2. 인증정보와 화면 상태 처리
[ ] 토큰·비밀번호를 URL, console, 분석 이벤트, 오류 수집 payload로 내보내지 않는가?
[ ] 인증정보의 브라우저 저장·복구 코드가 XSS/로그아웃 요구사항에 맞는가?
    localStorage를 sessionStorage로 바꾸는 것만으로 XSS 문제가 해결됐다고 하지 마.
    HttpOnly 쿠키로 이전해야 하면 서버 발급/프론트 연동 변경을 협업 작업으로 분리해줘.
[ ] 로그아웃 시 서버 무효화 API를 호출하고 민감 상태·캐시·진행 요청을 정리하는가?
[ ] 계정 전환 뒤 이전 사용자의 늦은 API 응답이 새 화면 상태에 섞이지 않는가?
[ ] 인증 만료·갱신 실패 시 무한 재시도나 중복 refresh 요청이 발생하지 않는가?
[ ] 버튼 숨김·라우트 가드를 서버 인가의 대체 수단으로 사용하지 않는가?

3. API·메시지·파일 처리
[ ] API 클라이언트가 인증 헤더/비밀값을 임의의 외부 URL로 전달하지 않는가?
[ ] 기존 인증 방식의 CSRF 토큰 전달 프로토콜을 정상적으로 구현하는가?
[ ] API 응답을 실제 런타임에서 검증하고 불필요한 필드/보호 필드를 요청에 다시 보내지 않는가?
[ ] postMessage 사용 시 origin·source·메시지 형식을 검증하고 임의 명령을 실행하지 않는가?
[ ] 파일명·미리보기·다운로드 URL을 안전하게 처리하고 서버 권한 거부를 무시하지 않는가?
[ ] 오류 응답을 HTML로 삽입하거나 내부 오류/비밀정보를 그대로 사용자에게 표시하지 않는가?

4. 검증
[ ] 검색·게시글·URL·파일명 등의 테스트 입력이 스크립트로 실행되지 않는가?
[ ] 정상 로그인/로그아웃/갱신/계정 전환과 오류 상황이 기존 기능을 유지하는가?
[ ] 가능한 항목은 기존 브라우저 테스트 도구로 회귀 검증했는가?

코드 수정 결과는 다음 형식으로 제출해줘.
항목 | 조치 완료/미흡/미대상/확인불가 | 변경 파일·위치 | 테스트 증거 | 잔여 작업

NGINX 설정 / Spring·인증 서버 설정 / 빌드·배포·OS 설정은 별도 표에만 기록해줘.
코드상 inline/eval 제거 또는 SSR nonce 연동이 필요하면 코드 작업으로 남기되,
CSP 헤더를 설정하는 작업 자체와 구분해줘. 고정 nonce를 만들지 마.
실행하지 않은 테스트나 실제 배포 반영을 완료로 표시하지 마.
KISA와 직접 연결되는 항목만 근거를 붙이고 별도의 '프론트 26개 합격'으로 표현하지 마.
```
